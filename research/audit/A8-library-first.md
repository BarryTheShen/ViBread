# ViBread A8 — library-first replacement audit

**Audit scope.** The target is the custom/own/BUILD surface in `PLAN.md` §5–§6. The workspace used for hands-on checks was `/tmp/audit/a8`; no product source was changed. Registry and repository maintenance observations are point-in-time signals, not guarantees. Package versions and license fields below are the versions resolved during this audit run; any missing license is explicitly marked **[UNVERIFIED]**.

## Scope and headline

The maintainable split is **library-first adapters around a small ViBread-owned truth and safety layer**, not replacing the product with one EDA or simulator:

* `circuit-json` + `@tscircuit/core` are a useful secondary artifact format and renderer input. They can represent labeled Arduino-like chips, source ports, traces, LEDs, resistors, pushbuttons, and pots; photoresistor/buzzer are generic chips/resistors. They do not preserve the full KiCad-style electrical-type vocabulary in the current source-port schema, and the current core output is coupled to generated IDs/layout. Keep the ViBread IR canonical.
* `@tscircuit/checks` is useful for structural/PCB/schematic checks, not a replacement for typed ERC or Uno current/voltage/resource rules. Its package/repository declares no license (**[UNVERIFIED]**).
* `circuit-json-to-spice`, `@tscircuit/ngspice-spice-engine`, and `eecircuit-engine` remove generic serialization/result parsing, but model coverage and license/maintenance boundaries mean the server still owns approved models, deck policy, limits, timeouts, and MCU/device coupling. Use the native `ngspice` CLI as the primary backend.
* XState v5 replaces most transition logic and supplies actor snapshot persistence. SQLite schema/migrations/queries can be replaced by Drizzle + `better-sqlite3`; `node:sqlite` is available in Node 22 but emits an experimental warning and has no first-party Drizzle driver in the installed release.
* Express 5, Pino, `express-rate-limit`/`rate-limiter-flexible`, YAML, sharp, and Eta are good glue dependencies. `better-sse` works and is MIT but its last registry modification was 2025-12-29, outside a six-month maintenance window at this audit; use only if that signal is acceptable or keep a very small SSE adapter.
* `avr8js` and `yaml` provide the CPU and scenario parser. No maintained, local, portable Wokwi-scenario runner plus all required functional part models was found. The runner, event queue, LED/button/pot/LDR/buzzer models, coverage, and fidelity labeling remain custom.
* StandardFirmata/ConfigurableFirmata are generic unsafe/manual protocols, not a netlist-aware self-test. Generated self-test firmware remains custom. Eta can render a fixed template and ArduinoJson 7.4.2 is MIT, architecture `*`, and explicitly supports NDJSON/JSON Lines and Arduino Uno/Nano-class boards.
* No drop-in solderless-breadboard placer/LVS/step generator was found. Boardwright is useful MIT prior art and a runnable perfboard/stripboard tool, but its own roadmap marks solderless breadboard support as future work. Keep the constrained board profile, placer/router, LVS, and step generator custom.
* sharp is the right crop/resize/composite primitive. HEIC conversion, fiducial rectification, marker detection, Claude API content blocks, schema validation, evidence hashing, and the “vision never overrides telemetry” policy remain glue.

## Integration notes

### Circuit JSON and tscircuit boundary

1. Treat Circuit JSON as a **derived, pinned artifact**, not the LLM contract. The current source schemas are strong for component/port/trace IDs, display labels, power/ground/pull-up/protocol attributes, schematic/PCB geometry, and simulation-result elements. They do not encode the complete KiCad electrical type set (`input`, `output`, `bidirectional`, `passive`, power-input/output, etc.) as source-port fields. ViBread must retain those semantics in its own IR and copy only a normalized subset into `pinAttributes`/provenance.
2. Keep adapters deterministic: `vibread partId/pinId/netId` ↔ `source_component_id/source_port_id/source_trace_id`; never expose generated tscircuit IDs as stable API IDs. Validate adapter output with `any_circuit_element` after removing undefined properties and using schema-compatible numeric arrangements. Include the ViBread IR hash in Circuit JSON metadata/artifact records.
3. Run tscircuit in a Bun worker or a tested Node ESM/bundler path. Direct Node import of the audited core release hit `ERR_UNSUPPORTED_DIR_IMPORT` in the `calculate-elbow/lib` dependency; `bun run` and `tsx --input-type=module` worked. `circuit-json-to-kicad` also required an explicit `polygon-clipping` install in this workspace, so lock and smoke the complete dependency graph before adoption.
4. Use `circuit-to-svg` for a secondary schematic view/PNG source if its ID/layout output is acceptable. Keep the primary accessible assembly/breadboard SVG owned by ViBread because Circuit JSON has no solderless-board electrical groups or step semantics.

### ERC and SPICE

1. Run ViBread’s board-profile rule engine first; `@tscircuit/checks` findings are a separate structural diagnostics namespace. Do not turn a tscircuit “no power pin” warning into proof of electrical safety.
2. Use `json-rules-engine` only with a closed operator/fact vocabulary. Store rules as versioned data and validate them with Zod/JSON Schema. Avoid remote/async facts in safety checks. Add deterministic diagnostic IDs and evidence URLs around rule-engine events.
3. Prefer a server-generated structured netlist AST or approved model IDs over accepting arbitrary SPICE text. Execute `ngspice -b` in a job-owned directory with timeout, output cap, no shell interpolation, and no `.include/.lib/.shell` from model input. Treat convergence failure as inconclusive. `eecircuit-engine` is a useful browser/local WASM-like option for scalar/vector parsing but is not a ViBread Arduino/device model.
4. Pin exact native/WASM engine and model versions. Vendor/license-review `circuit-json-to-spice` and `@tscircuit/ngspice-spice-engine` before redistribution because no package license was present in the inspected tarballs.

### Mission, persistence, and HTTP

1. Model long human waits as XState states and events, not promises held by an HTTP request. Store an event before/with every transition that has external effects; restore the actor from a persisted snapshot plus event/revision record after process restart.
2. `better-sqlite3` is the simplest Drizzle driver for Node 22 and the smoke path works. Keep `node:sqlite` behind an experimental feature flag until Drizzle has a stable direct adapter. Add unique constraints for `(revisionHash, actionHash, approvalId)`, one-shot approval consumption, and artifact hash.
3. Express 5 handles route/middleware/async errors; use Pino child loggers with `missionId`, `revisionHash`, `requestId`, and `channel`. Put rate limiting on bearer/mission identity as well as IP; use a Redis/SQLite-backed store when multiple workers are deployed. Do not use an in-memory store for a multi-process public endpoint.
4. `better-sse` supplies protocol framing, IDs, keep-alives, and channels, but ViBread still owns authorization, mission channel membership, replay policy, event retention, and disconnect cleanup. Its stale registry signal makes a small owned SSE adapter a reasonable fallback; retain the package only after a lockfile/security review.

### Simulation scenarios and physical safety

1. Borrow Wokwi’s human-readable shape (`name`, `version`, ordered `steps`) but define `vibread.sim/v1`; reject unknown steps, unbounded loops, arbitrary code, unspecified pins, and expectations that the selected backend cannot observe.
2. `avr8js` gives CPU/peripheral registers, not external hardware. Build models as pure deterministic state machines with explicit timing and fault injection. Put each run in a worker and record seed, virtual timestamps, firmware hash, device-model versions, traces, and unknowns.
3. Firmata’s reset behavior confirms the safety concern: StandardFirmata and ConfigurableFirmata configure non-analog digital pins as outputs on reset. A host command sequence can therefore energize a wired, unverified circuit before the host knows the netlist. Keep Firmata behind an explicit manual/unsafe mode and never call it a pass.
4. Generated self-test firmware should start all user pins high impedance, emit a design/firmware hash, use only server-approved sequences, abort on VCC sag/reset, restore inputs in cleanup, and emit bounded NDJSON. ArduinoJson is suitable for serialization but does not choose safe tests.

### Assembly and vision

1. No candidate understands ViBread’s solderless contact groups, split rails, exact through-hole footprints, MCU header geometry, and safety checkpoints. Keep the deterministic allocator/router/LVS and use boardwright only for perfboard algorithm/reference ideas.
2. Use a fixed camera contract: board powered off unless required, contrasting matte surface, top-down view, visible board edges/labels, fiducials, diffuse light, and explicit rejection on missing/occluded markers. `sharp` should handle auto-orientation, crops, size limits, and output encoding after HEIC conversion.
3. Claude receives an image block plus text/JSON questions; its response is a second opinion. Validate output against a strict schema and keep per-question `unknown`, crop IDs, confidence, and model/input hashes. A vision answer must not override MCU telemetry, ERC, or LVS.

## Recommended stack delta

**Adopt now (pinned):**

* `xstate@5.33.2` for the mission statechart and approval-wait state transitions.
* `drizzle-orm@0.45.3` + `drizzle-kit@0.31.11` + `better-sqlite3@13.0.3` for SQLite schema/query/migrations.
* `express@5.2.1`, `pino@10.3.1`, `express-rate-limit@8.7.0` for HTTP/logging/basic limits; use `rate-limiter-flexible@11.2.1` when a shared backend/identity limiter is needed.
* `yaml@2.9.1` for the owned `vibread.sim/v1` parser and `avr8js@0.21.1` for ATmega328P execution. Keep the custom worker runner and models.
* `eta@4.6.0` for a fixed, application-owned self-test template. Add `ArduinoJson` **7.4.2** to generated sketches only after the selected AVR compile smoke; emit NDJSON with a fixed schema.
* `sharp@0.35.4` for crops/resizing/compositing. Use `heic-convert@2.1.0` as a worker-thread fallback for iPhone HEIC and either `@techstark/opencv-js@5.0.0-release.1` or a smaller marker implementation after a real board-photo benchmark.

**Adopt as optional artifact adapters (license/compatibility lock required):**

* `@tscircuit/core`, `circuit-json`, and `circuit-to-svg` for secondary schematic/PCB/assembly artifacts and a modern visual cross-check.
* `circuit-json-to-kicad` for generated KiCad schematic/PCB handoff after explicitly installing/smoke-testing its geometry dependencies and running a real KiCad CLI validation.
