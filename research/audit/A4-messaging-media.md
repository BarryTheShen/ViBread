# A4 — Messaging + media verification

## Scope

This audit covers the messaging/media claims in `PLAN.md` §0, §5.11, §6.1–6.4 and the related `research/08-photon-landscape.md`. It checks `spectrum-ts@12.10.1`, Photon Spectrum plan/operations/OAuth facts, and `heif2jpeg@0.1.6` on this Linux host. Package installation, scripts, fixtures, and command output were kept under `/tmp/audit/a4/`; no product code was changed. The Anthropic key constraint was checked (`ANTHROPIC_API_KEY` is absent), so no LLM/API call was attempted. Photon cloud sends, account provisioning, promo redemption, and real iMessage delivery were not exercised without project credentials; those runtime/account-specific points are identified below.

Host/package smoke environment: `node --version` → `v22.22.1`; `/etc/os-release` → Ubuntu 26.04.1 LTS; `ldd --version` → GLIBC 2.43. Installed exact packages include `spectrum-ts@12.10.1`, `heif2jpeg@0.1.6`, `@photon-ai/cli@2.2.0`, TypeScript 5.9.2, and Node types 22.

## Integration gotchas discovered

- `Spectrum()` returns the merged app stream and lifecycle methods. In the terminal smoke, `app.messages` yielded a bound `Space`; attempting `app.space.get(...)` on the returned app produced `TypeError: app.space.get is not a function`. For proactive cloud conversations, narrow the provider (`const im = imessage(app)`) and use `im.space.create/get`; for the terminal fallback, drive the handler from an inbound space or the provider’s terminal interaction.
- `effect` is provider-specific and lives at `spectrum-ts/providers/imessage`; its constants are nested at `imessage.effect.message.*`. It is not a root `spectrum-ts` export. Local iMessage and non-iMessage providers have capability differences; keep readable plain content inside effects.
- `app.messages` is the right event contract for poll votes. Webhook delivery currently omits poll votes, so a webhook-only architecture cannot implement Go/No-Go approvals reliably.
- The terminal provider starts an external `tuichat` binary. Non-TTY input works through plain readline, but first use downloads the binary unless `TUICHAT_BINARY`/cache is prepared. This is distinct from Photon cloud connectivity.
- Spectrum package manifests declare MIT but do not declare an npm Node engine range. The Node 22 smoke is evidence for this version, not a future-version guarantee.
- `heif2jpeg` is native and fast in this environment, but its static libheif/libde265 build creates a third-party LGPL compliance boundary despite the npm package’s MIT label. A normal `npm install` does not place those codec source files or notices in the installed package.
- Native iMessage polls are an iOS 26 surface. Keep text alternatives in every poll flow. Free/Pro shared pools also require exact per-project recipient registration, and a user’s Apple email handle may differ from their phone number.
- Cloud line provisioning is account state, not a local package smoke test. The plan’s “Pro: up to 100 users” and promo path require dashboard verification before relying on them in a live demo.

## Recommended changes

1. Keep `spectrum-ts` pinned at `12.10.1`; update implementation snippets to import universal builders from `spectrum-ts`, `imessage`/`effect` from `spectrum-ts/providers/imessage`, and `terminal` from `spectrum-ts/providers/terminal`.
2. Implement CAPCOM as one long-lived `for await (const [space, message] of app.messages)` loop. Explicitly branch on `attachment`, `poll_option`, `text`, `reply`, and `reaction`; cache attachment bytes after one `read()`; bind approvals to the current revision.
3. Use native polls only as an enhancement. Always send a text fallback (`GO`, `NO-GO`, or numbered reply), especially for judges/teammates who may not be on iOS 26.
4. Before cloud testing, redeem `HACKWITHPHOTON` in Dashboard, verify Pro entitlement, register exact recipient handles under Project → Users (or `photon spectrum users add --phone ...`), and have each user text first. Record promo redemption as an operational prerequisite, not code behavior.
5. Keep Free/Pro as DMs. Require a Business dedicated line before promising native group creation, group membership events, or a shared team thread; otherwise use DM fan-out plus web/terminal state.
6. Run terminal provider tests with a pre-cached `tuichat` binary and non-TTY pipes. Route all late-night development traffic to terminal; keep cloud sends inbound-first, sparse, text-first, and within documented quotas.
7. Pin `heif2jpeg@0.1.6`, route by MIME, and retain the native-load/conversion smoke. Decide the LGPL codec redistribution plan (notices/source/relinkability or an alternate reviewed design) before shipping a container or binary.
8. Do not add Photon OAuth/OIDC to the hackathon path. Store project credentials only in the server environment; revisit OAuth if ViBread later needs per-user Photon Dashboard/project authorization. Add explicit `await app.stop()` signal handling in the standalone process.
