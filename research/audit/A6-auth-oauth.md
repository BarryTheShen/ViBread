# A6 — Identity and OAuth verification

## Scope

This is a point-in-time verification of the identity, MCP authorization, A2A security, Photon account-linking, Anthropic credential, and public-demo security claims in `PLAN.md` §§0, 5, and 6. The target is a one-day implementation on Node 22, Express, and SQLite for non-technical users.

Evidence was collected in the isolated workspace `/tmp/audit/a6-auth-oauth` (no product code was built). Runtime/package checks used Node `v22.22.1` and npm `9.2.0`. The installed candidates were `@modelcontextprotocol/sdk@1.30.1`, `@modelcontextprotocol/server@2.1.0`, Better Auth `1.7.6` plus its MCP/CIMD/OAuth-provider/passkey packages, `oidc-provider@9.12.2`, Express `5.1.0`, and SQLite through `better-sqlite3`. `ANTHROPIC_API_KEY` was checked and was absent (`ANTHROPIC_API_KEY=absent`), so Anthropic API behavior was not exercised against a live account. No managed-provider account, Photon project, or Claude Code OAuth sign-in was available; those portions are based on current first-party documentation and are marked accordingly.

## Integration gotchas discovered

1. **The package split is real.** `better-auth@1.7.6` is MIT and supplies core sessions/social login, but MCP/OAuth-provider/CIMD/passkey functionality is in separate `@better-auth/*` packages. Install and pin all of them. `@better-auth/mcp` has `@modelcontextprotocol/server` as a development dependency in its package metadata; ViBread must install the v2 server package itself.
2. **MCP v1 vs v2 is a protocol decision, not a cosmetic version bump.** `@modelcontextprotocol/sdk@1.30.1` is the v1 monolith. The v2 `@modelcontextprotocol/server@2.1.0` README says it implements 2026-07-28 and replaces v1. The v2 package describes a stateless/per-request HTTP handler; the old plan’s SSE/session assumptions should not be copied into the 2026 path.
3. **Resource metadata path placement matters.** The v1 SDK metadata smoke mounted `mcpAuthMetadataRouter` for `https://api.example.test/mcp`: `/.well-known/oauth-protected-resource/mcp` returned `200`, while the root path returned `404`. Better Auth’s MCP plugin returned both root and path-inserted aliases in the local smoke. Always test the exact deployed URL and include the `resource_metadata` challenge header.
4. **Better Auth schema migration is mandatory.** Starting it against an empty SQLite database failed with a schema mismatch listing `user`, `session`, `account`, `verification`, `jwks`, and OAuth tables. `npx auth@1.7.6 generate --config ./auth.config.mjs --output schema.sql -y` generated 58 lines of schema; applying it made metadata startup work. The deployment must run migration/generation before serving traffic.
5. **Better Auth’s Express handler must precede body parsing.** Use Express 5’s `app.all('/api/auth/*splat', toNodeHandler(auth))` before `express.json()`. Put the resource-server route and root PRM route outside the auth catch-all as appropriate.
6. **MCP authorization and web login are separate flows.** A logged-in ViBread browser user authenticates the AS; Claude Code is a separate OAuth public client and should receive a resource-bound access token. Do not reuse the browser’s session cookie as the MCP bearer token.
7. **CIMD fetch is SSRF-sensitive.** The Better Auth CIMD Node transport explicitly resolves only public addresses, pins the connection, keeps Host/SNI identity, and does not follow redirects. Do not replace it with a generic `fetch(client_id)` in a public AS. If DCR is temporarily enabled for older clients, rate-limit registration and keep client/resource allowlists.
8. **Scope source precedence matters.** Current Claude Code uses the resource challenge/PRM scope rather than requesting every AS catalog scope when no explicit `oauth.scopes` is configured. ViBread should put only the minimal current-operation scope in `WWW-Authenticate`, not all future admin scopes.
9. **Scope names are policy, not UI decoration.** Suggested scopes: `circuits:read`, `circuits:write`, `bench:request`. Keep design/software writes separate from physical requests. Return `403` with `insufficient_scope` for a missing software scope, but do not turn a physical request into an OAuth reauthorization that could be mistaken for human approval.
10. **Session cookie minimums:** keep Better Auth’s CSRF checks enabled; use exact `trustedOrigins` for the local origin and stable HTTPS tunnel; use `httpOnly`, `Secure`, `SameSite=Lax` cookies; never leave a localhost origin in a production allowlist. If a cross-origin frontend is introduced, add an explicit CSRF token/Origin check rather than weakening cookies.
11. **Quick tunnel URLs are poor OAuth identities.** A random `trycloudflare.com` hostname changes the resource URI, issuer/audience configuration, callback allowlist, and cookie origin. Use a stable named cloudflared hostname for a public OAuth demo, or regenerate every registered redirect/resource value before each run. The SSH tunnel’s browser URL can remain `http://localhost:8787` for local Google/GitHub callbacks.
12. **Social-provider callback values are exact.** Better Auth’s documented default paths are `/api/auth/callback/google`, `/api/auth/callback/github`, and `/api/auth/callback/apple`. Register both `http://localhost:8787/...` and the stable `https://public-host/...` values in Google/GitHub. Set `BETTER_AUTH_URL`/`baseURL` to the host currently being used; do not let a production process silently generate localhost callbacks.
13. **Apple is not a local fallback.** Apple’s Better Auth guide says localhost and non-TLS return URLs are unsupported, and setup needs Apple Developer credentials plus a renewable JWT client secret. Keep Apple out of the 36-hour critical path.
14. **Photon registration precedes outbound delivery.** Register/allowlist the user in the Photon project before CAPCOM attempts outreach. Use the user’s inbound message to prove control of the handle, then bind it. Poll votes require the long-lived SDK loop; webhook-only ingestion is not sufficient for the poll path.
15. **A2A security does not automatically inherit MCP transport semantics.** A2A card fields are OpenAPI-style declarations. Publish the A2A endpoint URL and bearer/OAuth requirements; enforce issuer, audience, scope, task ownership, and HTTPS at the server. Use the same AS only with separate resource audiences.
16. **Anthropic OAuth is not an integration credential.** Claude Code’s own subscription OAuth belongs to the unmodified Claude Code/Anthropic flow. ViBread must not collect or proxy it. A server-held API key is not a license to resell/intermediate usage for anonymous/public users.
17. **Do not log secrets.** Redact OAuth codes, access/refresh tokens, client secrets, magic-link codes, Photon credentials, mission capability tokens, and Anthropic keys. Store hashed one-time codes and token references where possible; keep the API key only in the server secret store.

## Recommended changes

1. **Replace the stack row in `PLAN.md`** with an explicit split: `@modelcontextprotocol/server@2.x` for MCP 2026-07-28, `@better-auth/mcp`, `@better-auth/cimd`, and Better Auth’s OAuth provider on SQLite. Retain `@modelcontextprotocol/sdk@1.30.1` only if the team intentionally targets the 2025-11-25 wire/transport line.
2. **Make Better Auth the primary hackathon implementation.** Use `betterAuth` with `jwt()`, `mcp({ resource: PUBLIC_MCP_URL, scopes: ['circuits:read','circuits:write','bench:request'], loginPage, consentPage })`, and `cimd({ metadataProfile: 'mcp-2026-07-28', fetchClientMetadataResource })`; generate/migrate SQLite before launch; mount `toNodeHandler` before `express.json()`.
3. **Enable CIMD, not open DCR, by default.** Keep a time-boxed DCR compatibility flag for clients demonstrably unable to use CIMD; rate-limit it and require the canonical MCP resource. Pre-register a client only for a known Claude Code fallback.
4. **Use Google as the primary browser login and GitHub as the second button.** Register exact local and stable HTTPS callback URIs. Add magic link only if an email sender is already working; defer Apple and passkeys.
5. **Add a stable public host before testing OAuth.** Prefer a named cloudflared tunnel or other stable HTTPS hostname. Keep the SSH-tunneled localhost origin for the bench browser and local OAuth callbacks.
6. **Implement web-to-iMessage linking as a one-time proof flow.** Hash/expire/consume the code atomically, register the Photon user first, accept only an inbound CAPCOM message from the matching registered handle, and bind it to the authenticated web account. Persist handle/user/project IDs and every link event.
7. **Publish one shared, least-privilege authorization vocabulary.** Use the same scope names in Better Auth metadata, MCP `WWW-Authenticate`, A2A `securityRequirements`, consent UI, and tool checks. Keep physical actions behind the human-only ApprovalBroker; OAuth/A2A clients can request but never approve.
8. **Treat the Anthropic key as a policy gate.** For the hackathon, restrict the server-key demo to the team/authorized test users and label it as owner-billed development usage. For a public end-user service, either require user-owned API/provider credentials or obtain an explicit commercial/legal decision; do not add Claude-subscription OAuth.
9. **If Better Auth cannot be configured in the first time-box, switch to WorkOS AuthKit** only if an account/domain is already available. The fallback still needs a ViBread PRM route, JWT/JWKS verification, resource audience checks, scopes, and the same human-only physical approval boundary.
10. **Add a smoke checklist before exposing a URL:** unauthenticated MCP `401` with `resource_metadata`; PRM and AS metadata curl; PKCE S256; resource in auth/token requests; wrong-audience `401`; missing scope `403`; browser session cookie attributes; CSRF rejection from an untrusted Origin; A2A bearer/OAuth card and task scoping; iMessage code replay rejection; no secret in logs.
