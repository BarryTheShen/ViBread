# A2 interoperability audit

## Scope

This audit covers the A2A, MCP, Claude Code remote-MCP, Claude Code Channels, and Express claims in `PLAN.md` §0/§5/§6 and `research/01-agent-interop.md`. Package probes were run only under `/tmp/audit/a2`:

```text
@a2a-js/sdk@1.2.1
@modelcontextprotocol/sdk@1.30.1
@modelcontextprotocol/server@2.1.0
@anthropic-ai/claude-code-linux-x64@2.1.283
express@5.2.1 and express@4.21.2 (isolated probes)
```

The environment has no `ANTHROPIC_API_KEY`. Claude Code probes therefore stop at `Not logged in · Please run /login`; they still completed MCP initialization and remote-server discovery. No product code was built.

## Integration gotchas discovered

- **A2A card security is descriptive.** `securityRequirements` does not install a verifier. The public card endpoint is also unauthenticated unless the application wraps it. Put bearer/JWT/OAuth middleware before JSON-RPC and decide separately whether the card is public or protected.
- **Use v1 A2A enum JSON exactly.** The package's v1 JSON codec emits uppercase protobuf enum names (`TASK_STATE_INPUT_REQUIRED`, `TASK_STATE_COMPLETED`). A lower-case `input-required` mapper is a v0.3/other-transport concern and will not match the observed v1 JSON output.
- **A2A v1 card JSON is protobuf-oneof shaped.** Bearer/OAuth declarations use `httpAuthSecurityScheme`/`oauth2SecurityScheme` and `authorizationCode` keys. A generic OpenAPI `{type, scheme, flows}` object is not what `AgentCard.fromJSON/toJSON` consumes.
- **A2A follow-up ordering matters.** The executor must publish a `task` or `message` first on every execution, including a continuation with `requestContext.task` already set. `DefaultRequestHandler` keeps the bus alive for input/auth-required states; terminal states close it.
- **`@modelcontextprotocol/sdk@1.30.1` tarball root is broken under Node ESM.** `package.json` exports `./dist/esm/index.js` and `./dist/cjs/index.js`, but `npm pack` shows neither file. Explicit `.js` subpaths work and are also the imports used by the Channels reference. Verify this exact package issue before using a bare root import.
- **MCP v1 high-level `McpServer` does not itself expose `elicitInput`.** Runtime inspection returned `typeof new McpServer(...).elicitInput === "undefined"`, while `typeof mcp.server.elicitInput === "function"`; use the underlying `Server` for client requests such as form elicitation.
- **Current Claude Code remote HTTP compatibility is directly reproducible without an API key.** With v1 `StreamableHTTPServerTransport`, Claude Code 2.1.283 reported the server `connected` and then stopped at `apiKeySource:"none"`/`authentication_failed`. This proves MCP discovery/initialization, not a model turn.
- **Claude Code's current OAuth and static-header paths are mutually distinct.** A configured `headers.Authorization` that is rejected is reported as a failed server instead of falling back to browser OAuth; remove the header to use OAuth.
- **Channel flags are hidden during research preview.** The docs say `--channels` and `--dangerously-load-development-channels` may not appear in `claude --help` even though they work. Custom channels also need `.mcp.json` consent and the per-session flag.
- **Channel relay authority is broad.** A sender allowed to answer the channel can approve/deny Claude Code's own Bash/Write/Edit calls. Keep this capability off unless sender authentication, allowlists, and exact request-ID handling are in place.
- **Express duplicate-version risk is real.** A2A accepts Express 4 or 5, but MCP v1 brings Express 5.2.1 as a dependency. Pin Express 5.2.1 at the app root for one predictable middleware type.
- **No model/API proof was attempted.** The Claude binary successfully initialized MCP but could not call Anthropic because no API key/login exists; model behavior, OAuth browser completion, and real Channel delivery remain unverified here.

## Recommended changes

1. Keep `@a2a-js/sdk@1.2.1`, but use its explicit server/client subpaths and implement a SQLite `TaskStore` plus authenticated Express middleware. Add a regression fixture that asserts raw v1 JSON contains `TASK_STATE_INPUT_REQUIRED` and `TASK_STATE_COMPLETED`.
2. Change the stack decision for the current Claude Code path from “MCP v2 required” to **MCP v1.30.1 for Channels and current remote HTTP compatibility**. Consider v2 only as a separate, future 2026-07-28 endpoint after a dual-era test.
3. Pin top-level `express@5.2.1` and `zod@4`; this satisfies A2A's `^4.21.2 || ^5.1.0` peer range and MCP v1's Express/Zod requirements.
4. Use the Channel docs' `.js` imports (`@modelcontextprotocol/sdk/server/index.js`, `server/stdio.js`, `types.js`) and keep the Channel process separate from the A2A server.
5. Treat A2A card OAuth/bearer entries as advertisement only. Enforce tokens with server middleware; use A2A client `AuthenticationHandler`/custom fetch for token refresh and `CallInterceptor` only for header injection.
6. For Claude Code remote setup, document `claude mcp add --transport http ... --header ...`; for OAuth servers, support DCR/CIMD + PKCE or provide a pre-registered client and the `--client-id`/optional `--client-secret`/`--callback-port` flags.
7. Gate custom Channels with the development flag only during local testing, require `channelsEnabled` and approved plugins for users, and leave Channel permission relay disabled for ViBread's physical-action approvals.
