# A3 browser + rendering verification

## Scope

This record audits the browser/upload/rendering claims in `PLAN.md` §0, §5, §6 and the related research reports `research/04-mcu-sim.md`, `research/06-physical-verify.md`, and `research/07-assembly-visuals.md`. The audit workspace was `/tmp/audit/a3`; no product code was changed. Runtime checks used Node `v22.22.1`, Linux x64, Vite `8.3.1`, React `19.3.0`, and Playwright Chromium 153.0.8010.12. No Arduino board was attached, so physical flashing, signature exchange with hardware, and a compiled Blink HEX run were not performed. No Anthropic API key was present; no API call was attempted.

A test artifact is only reported as a runtime result where it was actually exercised. Static-only claims are marked `[UNVERIFIED]` where appropriate.

## Integration gotchas discovered

- The flasher README is Node-centric even though the package exports a browser transport. The application should own the browser flow and not expose a raw package object to an agent.
- `webserial-flasher`'s `sendCommand()` writes before installing its response listener. A device response that arrives synchronously can be dropped by a non-buffering transport; the fake immediate-response test timed out, while a 1-ms delayed response passed. Keep transport buffering or patch/wrap this ordering before relying on tight protocol timing.
- `avr8js` is a CPU/peripheral core, not a file-format layer. HEX parsing belongs in the firmware adapter; `webserial-flasher` already exports `parseIntelHex`.
- `avr8js@0.21.1` declares npm `>=10.0.0`; this audit's npm 9.2.0 emitted an engine warning even though Node execution passed. Use the repository's supported npm version in CI.
- `elkjs`'s browser API expects its worker to be created by the page (`elk-api.js` + `elk-worker.min.js`). Loading `elk.bundled.js` inside a dedicated worker and trying to create a nested `Worker` did not work in Chromium. Use the standard page→ELK worker arrangement.
- `elkjs` is dual EPL/GPL metadata, unlike the plan's “EPL-2.0” shorthand. Legal review should choose whether the EPL option is sufficient and preserve the license file.
- Wokwi Elements are Lit custom elements with Shadow DOM and SVG output, not simulation models and not a breadboard. React 19 runtime integration works, but the shipped JSX declarations did not merge into React 19's `JSX.IntrinsicElements`; a wrapper or `React.createElement` is needed for strict TypeScript.
- tscircuit's direct `@tscircuit/core` runtime has a large peer/dependency surface. The renderer can consume hand-authored Circuit JSON without bringing the entire evaluator into the server, which is a safer first integration.
- `circuit-to-svg` reports ISC in npm metadata but ships no LICENSE file in the installed tarball. Record the ISC license and retain package/source attribution; verify the exact legal notice before publishing.
- `@resvg/resvg-js` selects a platform-specific native optional dependency. Keep the Linux x64 GNU package in deployment artifacts and test the deployed libc/architecture, rather than assuming a universal Node binary.
- Quick Tunnels return an SSE response with headers but no streamed body in the live probe. Use polling for the phone path exactly as the plan says.
- Web Serial requires a transient user activation for first-time `requestPort()`; `getPorts()` can enumerate prior grants. `http://localhost` is secure, but a raw remote HTTP address is not. The API is now available in Firefox 151 desktop as well as Chromium-family browsers, subject to Firefox's permission model.

## Recommended changes

1. Change the flasher claim from “browser usage is documented” to “browser transport is exported; ViBread owns the browser adapter.” Pin `webserial-flasher@1.0.1`, add a buffered-transport/physical smoke, and preserve an STK500 fallback.
2. Add a firmware adapter that uses `parseIntelHex` (or a separately tested parser) before passing bytes to `avr8js`; do not imply avr8js has HEX support.
3. Keep `avr8js@0.21.1` for Node and browser workers, with explicit peripheral capability reporting and no analog-fidelity overclaim.
4. Use `@resvg/resvg-js@2.6.2` for deterministic Node PNG export. Track, but do not silently adopt, the `2.7.0-alpha.*` line.
5. Prefer `circuit-to-svg` plus `@tscircuit/schematic-viewer` for schematic presentation after mapping ViBread IR to Circuit JSON. Use a tscircuit `<chip>` representation for Arduino labels, but retain ViBread's own board/breadboard SVG and LVS truth.
6. Keep `@wokwi/elements` behind a React 19 adapter for glyphs only; add a local JSX typing wrapper or use `React.createElement`. Do not search for a nonexistent Wokwi breadboard element at integration time.
7. Keep hand-written union-find for hole-level LVS; add Graphology only if broader graph algorithms justify its object overhead.
8. Add React Query polling to Build Mode, React Router routes, and react-markdown for safe agent text. Pin Node 22.22+ if using `react-router@8`.
9. Keep Quick Tunnel phone transport polling and state the 200 in-flight/no-SSE/no-SLA limits in deployment notes. Use a managed named tunnel if SSE becomes a requirement.
10. Update browser support copy to “Chrome/Edge tested; Firefox 151 desktop also implements Web Serial; feature-detect and require a secure context,” rather than “Chromium-only.”
