# A1 agent-core verification record

## Scope

This audit verifies the Claude Agent SDK and direct Anthropic API claims used by ViBread's plan, using a clean workspace at `/tmp/audit/a1` and the exact requested package versions:

- `@anthropic-ai/claude-agent-sdk@0.3.283` (bundles Claude Code `2.1.283`)
- `@anthropic-ai/sdk@0.128.0`
- `@modelcontextprotocol/sdk@1.30.1`
- `zod@4.6.5` (the installed Zod 4 version selected for the requested peer range)

The host is Ubuntu 26.04, x86_64, glibc 2.43, Node `v22.22.1`, npm `9.2.0`. `ANTHROPIC_API_KEY` is absent. Model-turn behavior was therefore not tested against the network; API surfaces were verified from installed declarations, package metadata, official documentation, and offline request/startup probes. No ViBread product code was built.

## Integration gotchas discovered

1. **Root entry and `/core` have different runtime identities.** The official TypeScript docs state that the package root inlines its own Zod and MCP SDK copies, while `/core` imports peer packages from `node_modules`; they must not both be imported in one process. The root smoke test produced an SDK MCP instance whose constructor was not `instanceof` the separately imported `@modelcontextprotocol/sdk` `McpServer` (`false`). The same test through `@anthropic-ai/claude-agent-sdk/core` returned `true`. Use one entry consistently; use `/core` when shared MCP/Zod class identity matters or when bundling.
2. **npm 9 installed both Linux x64 binaries.** Both glibc and musl package directories appeared even though this host is glibc. The SDK chose the glibc path correctly, but a container can pay the install-size cost unless the nonmatching musl package is pruned as the official docs recommend. Do not delete the glibc package; `pathToClaudeCodeExecutable` is only needed for skipped/custom binaries.
3. **`allowedTools` is an approval list, not a capability boundary.** With omitted `tools`, unlisted built-ins remain available. `bypassPermissions` approves unlisted tools unless a deny/ask rule or special interaction exception applies. ViBread's capability boundary must be `tools: []`, explicit `disallowedTools`, strict MCP configuration, and server-side policy—not a model-facing allowlist.
4. **`canUseTool` is not an invariant hook.** Auto-approved calls and `dontAsk`/`permissionPrompts:'none'` bypass it. A `PreToolUse` hook runs first and can deny even in bypass, but its timeout cancels the hook and prevents the tool call; the hook must handle timeout/abort as a safety decision.
5. **`settingSources: []` is narrower than “no external policy.”** It disables user/project/local filesystem settings, but endpoint-managed policy loads regardless. `strictMcpConfig` blocks the documented project/user/plugin/connector MCP sources, not every possible managed policy input. Keep server-side authorization authoritative.
6. **The SDK subprocess is not a pure HTTP client.** The bundled native process starts locally, performs initialization/auth, and maintains a session. Process count, RSS, transcript cleanup, and subprocess shutdown belong in the Node server's capacity plan.
7. **Structured output naming changed.** The installed direct SDK and current docs use `output_config.format`; older beta material used `output_format`. Do not copy the old parameter into the ViBread Messages fallback.
8. **Haiku's alias versus snapshot matters.** The current page calls `claude-haiku-4-5` an alias but lists `claude-haiku-4-5-20251001` as its API ID. Pin the dated ID when replay/determinism matters; otherwise the alias is currently supported.
9. **Sessions store conversation, not a board snapshot.** Persist IR revisions, artifacts, approvals, serial observations, and hardware identity in ViBread's own store. Resuming an SDK transcript cannot roll back breadboard state or files by itself.
10. **Commercial terms are materially different from the direct SDK's MIT dependency.** `@anthropic-ai/sdk@0.128.0`, MCP SDK 1.30.1, and Zod are MIT/compatible, but the Agent SDK/native Claude Code component is governed by Anthropic commercial/legal agreements. A public hackathon dependency declaration is not permission to offer a shared subscription-backed hosted service.

## Recommended changes

1. Keep the Agent SDK on Node 22 and pin `@anthropic-ai/claude-agent-sdk@0.3.283`, `@anthropic-ai/sdk@0.128.0`, `@modelcontextprotocol/sdk@1.30.1`, and Zod 4 in the lockfile. Prefer one SDK entry (`/core` if the server also manipulates MCP SDK classes).
2. Make the security options explicit for every mission: `tools: []`, `mcpServers` with only in-process ViBread servers, `strictMcpConfig: true`, `settingSources: []`, a real absolute `cwd`, and explicit `permissionMode`/`allowDangerouslySkipPermissions` values. Do not use `allowedTools` as the sole restriction.
3. Expand the permission matrix to include `dontAsk` and `auto`. Treat `canUseTool` as the prompt fallback and put the physical/BOM deny-by-default check in `PreToolUse` with an explicit timeout and abort handling. Never run bypass for physical actions; if software-only bypass is retained, set `allowDangerouslySkipPermissions: true` intentionally and retain deny hooks.
4. Add a typed SSE adapter that handles the full `SDKMessage` union and distinguishes `SDKPartialAssistantMessage` (opt-in) from complete assistant/result messages. Keep API keys and the native subprocess server-side.
5. Add a startup/image smoke check: run the bundled glibc binary `--version`, assert the expected `2.1.283`/SDK match, and remove the musl package from glibc production images. Set `pathToClaudeCodeExecutable` only for a custom/extracted binary.
6. Put a bounded concurrency/idle-close policy around one native process per active mission. Use `startup()` to move spawn/initialize latency off the request path, but prewarm only a small number of option profiles; use persisted session IDs plus ViBread task state for human pauses.
7. Replace any plan language implying “Sign in with Claude” or user subscription routing. Use an approved API-key/provider arrangement under Commercial Terms, or a user-supplied supported credential; obtain Anthropic approval before any alternate end-user billing/auth model.
8. Include the proprietary Agent SDK/Claude Code legal notice, Anthropic branding restrictions, data-retention/feedback disclosure, current model prices, and the usage-policy/human-review assumptions in the public demo documentation.
