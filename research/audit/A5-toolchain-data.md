# Scope

This audit covers the toolchain/data claims in `PLAN.md` sections 0, 5, and 6 and the related firmware/SPICE research (research/03 and research/05): Arduino CLI/core installation and compilation, ngspice batch operation, SQLite choices on Node 22, Node release/support constraints, cloudflared installation on Ubuntu 26.04, and the available container resources. Commands were run in `/tmp/audit/a5`; no product code was built. The Anthropic key boundary was checked and `ANTHROPIC_API_KEY` was absent, so Agent SDK runtime/API calls were not exercised; only package metadata and resource facts were checked.

# Integration gotchas discovered

- Arduino CLI configuration initialized successfully with all directories under the job workspace. The compile result's `builder_result.build_path` points into the cache, while `--output-dir` owns the published artifacts. Never use one output/build directory for concurrent writers; use unique job IDs and serialize first-time core/index installs.
- FQBN options matter: the Nano's `atmega328` and `atmega328old` choices produce the same application HEX in this Blink smoke but different bootloader-inclusive HEX/BIN artifacts. Store the option in the board profile; do not infer it from `Arduino Nano` alone.
- Successful `--json` output is not a fixed schema instance: clean output omitted `error` and `builder_result.diagnostics`, while warning output populated structured diagnostics. Keep raw compiler streams and tolerate missing/null fields.
- ngspice's `i(VLED)` is negative for current delivered out of a positively oriented voltage source; the circuit forward current is its negation. Parse/label this rather than reporting a negative LED load. Server-owned controls must reject untrusted `.include`, `.lib`, `.shell`, and arbitrary control text.
- `better-sqlite3` still runs npm's implicit `node-gyp rebuild` command, but its GYP conditions make that a no-op when the packaged host prebuild exists. A future platform/ABI without a prebuild will need a compiler toolchain, so retain a startup/install capability check.
- Built-in `node:sqlite` is flag-free from Node 22.13 onward but remains experimental in 22.22.1; the warning is an observable compatibility signal, not harmless stable API noise.
- `avr8js@0.21.1` declares npm >=10 while this host has npm 9.2.0. Upgrade npm in the build image even though Node 22.22.1 satisfies its Node floor. Vite 8's latest metadata raises the Node floor to >=22.12, so an unpinned Vite upgrade can break an older Node 22 image.
- Cloudflare's package docs list distro-specific suites only through Ubuntu 24.04 but also provide a recommended `any` Debian-based repository. Ubuntu 26.04 should use `any`; do not invent a `resolute` repository path. The direct binary is simpler for an ephemeral container.
- Relevant distribution boundaries: Arduino CLI is GPL-3.0 and ngspice has heterogeneous licensing documented in `COPYING`; invoke them as external tools and retain notices rather than embedding/copying implementation code. `better-sqlite3` and `avr8js` are MIT; `@resvg/resvg-js` is MPL-2.0 and needs its own notice treatment if shipped.

# Recommended changes

1. Keep `arduino-cli` v1.5.1 and `arduino:avr@1.8.8` as external, checksum-pinned tools. Create job-owned `ARDUINO_DIRECTORIES_*` paths, unique output/build paths, and a serialized installation phase.
2. Update the firmware evidence contract to model optional `error`/`diagnostics` fields, preserve raw compiler streams, and budget roughly 0.4 s for a warm CLI compile until application-specific p50/p95 data exists.
3. Keep better-sqlite3 13.0.3 as the default store; test that the host ABI has a prebuild and set npm >=10 to satisfy avr8js. Do not switch the primary store to Stability-1.1 `node:sqlite` yet.
4. Keep Node 22 for this build, pin a 22.22.x patch (or later tested 22.x), and document Node 24 Active LTS as the migration target. Pin Vite and enforce `engines` in CI.
5. Use ngspice 45.2 through a bounded child process with a generated deck/control block, raw output capture, timeout, and approved model catalog. Treat SPICE results as nominal cross-check evidence.
6. Install cloudflared from the signed Cloudflare `any` apt repository for managed hosts, or the checksum-verified official amd64 binary for the container image; pin 2026.9.3 in the image/lock record.
7. Size the worker scheduler from measured RSS/CPU once real Agent SDK runs are possible; the current 16-core/123-GiB baseline supports concurrency but is not a load benchmark.
